# Domain docs

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root defines domain terms.
- `docs/adr/` holds architecture decision records.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area you will work on.

If these files are missing, proceed silently. Create them through
the domain-modeling skill when terms or decisions are resolved.

## Use domain terms

Use the glossary's terms in issues, proposals, hypotheses, and tests.
If a needed term is missing, check whether existing vocabulary fits.
Record real gaps for domain-modeling.

## Conflicting decisions

If a proposal contradicts an ADR, identify the ADR and explain
why the decision should be revisited.
